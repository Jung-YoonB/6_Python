## 2. STEP 6 · "정확도 84 % 인데 연체를 못 잡는다" 의 원인

| 모델 | 정확도 | 정밀도 | 재현율 | F1 | AUC | 연체 예측 건수 |
| --- | --- | --- | --- | --- | --- | --- |
| DummyClassifier | 0.8193 | 0.0000 | 0.0000 | 0.0000 | 0.5000 | 0 |
| LogisticRegression | 0.8193 | 0.0000 | 0.0000 | 0.0000 | 0.4814 | 0 |
| LogisticRegression(balanced) | 0.4667 | 0.1708 | 0.5061 | 0.2554 | 0.4817 | 1,446 |
| RandomForest | 0.8193 | 0.0000 | 0.0000 | 0.0000 | 0.4901 | 0 |
| RandomForest(balanced) | 0.5470 | 0.1638 | 0.3668 | 0.2264 | 0.4878 | 1,093 |

1. **Dummy 와 RandomForest 의 정확도가 같은 이유** : 두 모델 모두 테스트 전체를 "정상" 으로 예측했다(연체 예측 0 건).
   연체가 17 % 뿐이라 연체 확률이 기본 임계값 0.5 를 넘는 경우가 없어, RandomForest 도 결국 다수 클래스만 답했다.
2. **담당자 상황의 원인** : `class_weight` 를 쓰지 않은 모델들처럼 **정확도는 80 % 대지만 재현율이 0** 인 상태.
   불균형 데이터에서 정확도는 "정상 비율" 만큼 공짜로 올라가는 지표라, 연체를 하나도 못 잡아도 높게 나온다.
   -> 연체 탐지 성능은 **재현율·정밀도·F1·AUC** 로 판단해야 한다.
3. **`class_weight="balanced"` 를 쓰는 이유** : 적은 쪽(연체)을 틀릴 때 더 큰 벌점을 줘서 모델이 연체를 예측하게 만든다.
   정상을 연체로 잘못 보는 경우(FP)가 늘어 정확도는 떨어지지만, 목적이 "연체 잡기" 이므로 재현율이 0 -> 0.37~0.51 로 오르는 것이 의미 있다.

> 참고 : 모든 모델의 AUC 가 0.48~0.49 로 무작위(0.5) 수준. 현재 피처(요일·시간·가입기간·결제수단 등)로는 연체와 정상을 구분하는 힘이 거의 없다.

## 3. STEP 7 · FN 과 FP 의 의미와 리스크

RandomForest(balanced), 임계값 0.5

| | 예측 정상 | 예측 연체 |
| --- | --- | --- |
| **실제 정상** | TN 1,298 | FP 914 |
| **실제 연체** | FN 309 | TP 179 |

| 구분 | 의미 | 리스크 |
| --- | --- | --- |
| TP | 장기 연체를 미리 잡아냄 | 독촉 알림으로 방치·손실 예방 |
| **FN** | 장기 연체를 **놓침** | 자전거 방치, **회수 인건비 + 미수납 연체료** (건당 15,000원) |
| **FP** | 정상 이용자를 **괜히 의심** | 불필요한 독촉 연락, **고객 불만** (건당 2,000원) |
| TN | 정상을 정상으로 판단 | 비용 없음 |

**더 치명적인 쪽은 FN.** 건당 비용이 FP 의 7.5 배이고, FP 는 문자 한 통으로 끝나지만 FN 은 직접 회수하러 가야 하고 연체료도 받지 못한다.
따라서 FP 를 어느 정도 감수하더라도 **재현율(FN 줄이기)을 우선**해야 한다.

## 4. STEP 8 · 비용 기반 임계값 선택 근거와 절감 효과

총비용 = FN x 15,000 + FP x 2,000 (임계값 0.05 ~ 0.95, 0.05 간격)

| 임계값 | TP | FN | FP | 재현율 | 정밀도 | 총비용 |
| --- | --- | --- | --- | --- | --- | --- |
| 0.05 ~ 0.30 | 488 | 0 | 2,212 | 1.0000 | 0.1807 | 4,424,000 |
| **0.35** | **488** | **0** | **2,211** | **1.0000** | **0.1808** | **4,422,000 (최소)** |
| 0.40 | 483 | 5 | 2,198 | 0.9898 | 0.1802 | 4,471,000 |
| 0.45 | 444 | 44 | 2,023 | 0.9098 | 0.1800 | 4,706,000 |
| 0.50 (기본값) | 179 | 309 | 914 | 0.3668 | 0.1638 | 6,463,000 |
| 0.55 | 13 | 475 | 81 | 0.0266 | 0.1383 | 7,287,000 |
| 0.60 이상 | 0~1 | 487~488 | 0 | 0.00 | - | 7,305,000 ~ 7,320,000 |

| 비교 | 총비용 |
| --- | --- |
| 아무 예측도 안 함 (전부 정상, FN 488 건) | 7,320,000원 |
| 기본 임계값 0.5 | 6,463,000원 |
| **최소 비용 임계값 0.35** | **4,422,000원** |
| **절감액 (아무 예측도 안 함 대비)** | **2,898,000원 (39.6 %)** |

**선택 근거**
- FN 1 건(15,000원)이 FP 7.5 건(2,000원 x 7.5)과 같은 손실이라, 임계값을 낮춰 FN 을 줄이는 쪽이 이득이다.
- 손익분기 확률 = 2,000 / (15,000 + 2,000) ≈ **0.118** -> 연체 확률이 12 % 만 넘어도 독촉하는 편이 싸다.
- 그래서 기본값 0.5 가 아니라 **총비용이 최소인 0.35** 를 선택. F1 기준이 아니라 **비용 기준**으로 정했다.
  (이번 데이터는 F1 최대도 0.35 로 같게 나왔지만, 거의 전원을 연체로 예측해 재현율이 1.0 이 된 우연의 일치)

**정직한 해석 (한계)**
- 최적 임계값 0.35 는 사실상 **테스트 2,700 건 거의 전원에게 독촉**하는 선택이다.
- 실제 연체율(약 18 %)이 손익분기(12 %)보다 높아서, 이 비용 구조에서는 **누구에게나 독촉하는 것**이 이미 이득이다.
  모델 없이 전원 독촉하는 비용(4,424,000원)과 최적 비용(4,422,000원)이 거의 같다.
- 즉 절감 효과는 모델의 예측력보다 **"비용 구조상 공격적으로 독촉하는 정책"** 에서 나왔다. AUC ≈ 0.49 라 현재 피처로는 연체할 대여만 골라내지 못한다.
